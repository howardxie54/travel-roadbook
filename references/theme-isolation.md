# 目的地主题隔离与控件颜色

基础模板保留布局、内容结构与交互；作者原网站的草绿、沙色与旧状态色不得成为其他目的地的默认皮肤。不要只改七个主色变量、只补日本页面，也不要把“去掉绿色”当成通用验收规则：绿色旅行主题仍可合理使用绿色。验收目标是每个控件的颜色来自当前旅行主题。

## 一条完整的构建路径

1. 根据旅行内容保存 visualTheme.palette 的 bg/surface/ink/muted/line/accent/accent-soft，说明设计依据。theme_tokens.py 负责派生主动作 hover/pressed、次动作 hover/pressed、前景色、焦点环、禁用色、导航透明层与阴影，不手填作者色号。
2. 独立的目的地装饰、字体、标题与素材样式保存到项目内 CSS，使用 visualTheme.stylesheet（例如 japan.css）。生成器按基础模板 → 可选目的地示例 → 项目装饰 → 当前主题变量与固定组件 → control-theme.css 的顺序内嵌。最后的控件颜色与功能结构由包内契约保护，离线保存保留同一套样式。
3. 不在最终 HTML 末尾追加手工颜色补丁，不修改生成文件来掩盖包内遗漏。改包内对应源文件，重新生成并验证其他配色。

按钮实底统一用 accent 与 on-accent；次要按钮用 accent-soft 与 on-soft。悬停、按下与禁用使用派生变量，文字目标对比度至少 4.5:1。明亮的主色需要深色前景，不能强制所有主题用白字。装饰图像、授权底图、菜品实拍不受 UI 色号扫描约束，不为了检查把图片变成单色。

## 原网站残色容易藏在哪里

- .actions .btn:not(.alt) 比 .btn 更具体；只覆盖 .btn 的文字或尺寸会留下原绿色底。
- .hotel-map-link::before 曾额外画一层胶囊；新的完整按钮只使用自身底色，control-theme.css 取消重复伪元素背景。
- .is-pressing、:active、:hover、[aria-current]、[aria-selected]、details[open] 与减少透明度分支必须随主题，不能保留旧色。
- 图标圆底、焦点环、box-shadow、选择文字、滚动条、浏览器 theme-color、占位矢量与 favicon 同步当前主题；不复制固定日序号对应的草绿沙色。

## 实际验收与证据边界

运行 scripts/check_theme_contract.py：检查基础模板没有独立 UI 色值，派生色的前景对比，以及内置状态契约资源接入。此脚本是静态与数值检查，不代表浏览器测试。

至少用深色主色与明亮主色两套显著不同的非默认主题，直接用生成器构建，不依赖某个旅行项目的手工补丁。浏览器在窄屏与桌面分别检查：地点主按钮、备用地图与复制、酒店按钮、路线播放、整天入口、快捷入口、日期选中、美食展开/动作、手机与桌面导航。查看 computed style 和 ::before/::after，普通、展开、焦点、真实按下状态都要检查；可用自动化工具时检查 hover/active/disabled 与旧色回归。记清实际工具能够覆盖的状态，静态状态夹具不能声称是真实手机按压。

复核日期切换、抽屉、订单与离线导出没有因换色退化；纯样式更新保留原 trip 内容及预订，保存旧样式和构建快照，递增 styleVersion。未验证的真实设备保留限制，不因色号扫描通过就宣称任意目的地与宿主完全通过。
