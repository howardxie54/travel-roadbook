# 目的地设计、长行程和地图

保留功能，不等于复刻作者的视觉皮肤。先从用户计划提取城市、实际景点、交通和感受词，再搜索官方目的地资料与地标以核实事实。用户提供的审美联想可直接作为设计方向，但不能称为目的地的唯一文化风格。给出主题色、字体、标题处理与装饰的理由；标题可以华丽，但无需每字加动效。

内置 thailand-summer 是金黄/果肉黄/夏日/少量海蓝的已实现示例。其他目的地由助手基于功能模板生成独立主题 CSS 和必要文案，不要求安装外部设计 Skill，不宣称只换目的地名称就已自动完成所有主题设计。

布局随天数与屏幕选择：少量天数可保留卡片；5 天以上优先紧凑路线列表、时间轴或按城市分组。7/14 天不能硬套四列换行，更不能让末尾奇数卡片孤立。逐日导航保持单行横向滚动，选择或键盘切换后活动项自动进入可见区；保留可读的当前日期和城市。长列表可设置局部滚动，不能为了省空间删除每日内容。按 components-and-maps.md 的固定组件规范实现；验证 1–14 天与窄屏。

城市位置必须使用经过核实的经纬度与同一投影，禁止根据视觉效果随手放置。主要游玩地区使用大主图，出发/离开使用小概览图；标明北向、底图来源、城市点与导航入口的差别。城市中心不能当作机场或酒店坐标。

可用地图数据/授权底图时绘制地理地图，或通过允许的地图显示与截图方式得到底图；不能由图像生成模型决定城市地理。图片或截图与路线层必须配准，无法保证则使用经纬度地理轮廓，明确其精度。OSM 在线瓦片不能批量预取供离线打包，离线用允许分发的数据或素材。本例内嵌 Natural Earth 地理轮廓，在线加载少量当前显示范围的 OSM 瓦片；可内嵌许可允许的 OSM 道路矢量，保留署名与来源。

角色与交通组合应有同一画风，默认可用中性素材，但当用户提供小猫/交通参考时依照参考生成。透明图可使用 sprite atlas，由 SVG viewBox 选择象限；生图后检查杂边，可再编辑。每一段保存 from、to、mode 与信息来源，按用户文字提取并标准化飞机/火车/汽车/自行车；提到“高铁”可归为 train 显示，但不因此认定当地确有高铁线路。待定区段只在插画上沿用最近前段已知方式，没有前段已知则用全程首个已知方式；全程待定用中性点，真实状态仍待定。自动跟随路线区段换图，最终页面不放装饰交通选择器。例子的交通不能写进实际计划。逐段播放包括局部放大图，不能只播放第一段。按路径切线与素材原始方向镜像左右，保持角色直立、限制倾斜，检查往返方向。Remotion 只在需要视频输出时作为可选依赖，网页路线动画不依赖它。

此次组合插画使用内置 imagegen，提示为透明 2×2 atlas：左上小猫飞机、右上小猫 SUV、左下小猫火车、右下小猫自行车，统一粗黑手绘线条，全部朝左，无文字和背景。参考由用户提供；对外打包该角色前仍需确认素材权利。
