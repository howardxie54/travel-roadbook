# 导航与普通用户交付

桌面导航是已验证原网站右侧悬浮岛的可移植组件，颜色不固定为草绿。build_original.py 内嵌 desktop-navigation.html/css/js；theme_tokens.py 从本次主题派生底色、透明底、悬浮态、文字、选中态和投影，保证文字可读。不要随滚动改变整套导航颜色。检查背景轮廓分离与文字对比两个问题。

宽度至少 1360px、高度至少 501px 且右侧实际留白足够才显示，避免遮挡内容；滚动超过 240px 出现。四个章节与手机一致，只有一个 aria-current，键盘可达。回到顶部、减少动效、缩窄窗口与打印都有对应状态；隐藏导航退出 Tab 顺序。手机底栏独立保留，不把桌面组件硬塞到手机。

## 一份粗略计划如何交付

1. 读取 SKILL 和核心引用，提取出发地、目的地、天数、已知交通，不要求用户填写内部字段。只补问影响当前生成的关键信息，未知可先留空。
2. 助手整理 trip.json，生成器 normalize_input.py 为缺失的可选字段补安全默认值；不能把未知行程填成已确认。最少可用 `{ "duration": 7, "origin": "上海", "destinations": ["曼谷", "芭提雅"] }` 生成完整待补充页面。这是结构基线，正式预览仍由助手结合计划拟定并明确标注城市分配。
3. 研究目的地，保存 visualTheme.palette、basis、来源和素材类型；没有额外设计 Skill 也沿用内置组件。宿主没有联网/生图能力时交付矢量与文字版本，不伪造搜索结果、实拍或精确地图。
4. 用 scripts/build_original.py 构建；运行时缺失可按模板直接产出自包含网页。交付 index.html、trip.json、history 和说明，后续对话继续读取这些文件，不依赖聊天缓存。
5. 按 preserved-features.md 验收全部功能，手机/桌面均检查；有目的地主题不等于只换标题或色号。示例的美食照片、小猫 atlas、道路文件不属于基础包依赖，也不能复制用户的私有预订。

验收覆盖：粗略输入、空事件、未填酒店地址、带时区倒计时、跨境导航、1–14 天、长城市名、就地预览、键盘/手机手势、重复修改与明确版本恢复、无网络下载、桌面导航避让。记录结果和限制，不把生成器测试说成全部宿主和任意目的地已通过。

重建和主题延续：自定义目的地样式、装饰应保存为项目相对路径的文件或明确构建步骤，随 styleVersion 一起快照。不要只修改生成后的 HTML，也不要在项目脚本硬编码作者电脑的 Skill 路径；使用实际安装路径的命令参数或相对布局。基础模板已处理选中日期边框、展开图标、路线色和 SVG contain，助手不需逐个补修。
